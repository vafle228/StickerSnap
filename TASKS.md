# StickerSnap — задачи

Единый список работ проекта. Правила разработки — в [AGENTS.md](AGENTS.md), команды
и проверки — в [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md), дизайн — в

## Как вести список

- Агент обновляет статус, критерии, результат и проверки по ходу работы.
  Мелкие пункты внутри текущего запроса добавляет самостоятельно; новые крупные
  направления сначала согласовывает с пользователем. Ссылки на PR необязательны.
- Статусы: **Запланировано → В работе → На проверке → Готово**.
  **Предложено** — идея, ещё не согласованная для выполнения.
  **Заблокировано** — есть конкретное препятствие; **Отложено** — принято решение не продолжать.
- Для задачи записывать ID, ожидаемый результат, затронутые части, критерии готовности,
  выполненные проверки и оставшиеся ограничения. Не переносить прошлый успех теста на новый код.
- «Готово» относится к согласованному объёму задачи. Отдельно указывать, если результат
  только локальный: готовность не означает merge, production-деплой или выпуск релиза.
- Не восстанавливать статусы старых B/S/R-задач по комментариям в коде.
  История внешнего backlog здесь не воспроизведена; реализованные функции описаны в AGENTS.
- Приоритет новых продуктовых задач определяет пользователь. Пока новых согласованных
  продуктовых задач нет; ниже — результаты текущей работы и технические задачи.

- [x] Проверены lint, typecheck, сборка SPA и тесты DS/SPA.
- [ ] Проверить визуально и интерактивно в браузере: обе темы/акценты, узкий экран,

## DEV-001 — Согласовать переводы строк с Prettier в Windows

**Статус:** Предложено, не начато. **Дата:** 2026-11-12.

**Наблюдение при первичном исследовании:** корневой `npm run format:check` сообщил ошибки
в 375 существующих файлах старой рабочей копии.
На проверенных неизменённых файлах (`Button.tsx`, `App.tsx`, Mini App `index.html`)
содержимое HEAD проходит Prettier, а рабочая копия отличается только CRLF вместо LF.
Изменённые в текущей задаче TSX/CSS/JS/package.json/TESTING проходят форматирование.
Полная проверка с `--end-of-line auto` проходит; стандартная команда без override остаётся красной.

**Предлагаемое действие:** выбрать общую политику переводов строк в `.gitattributes`
и нормализовать репозиторий отдельным техническим изменением, не смешивая его с продуктовой задачей.

**Критерии после согласования:**

- [ ] Чистая Windows-копия проходит стандартный `npm run format:check` без CLI overrides.
- [ ] Generated-файлы и Linux CI остаются воспроизводимыми.
- [ ] В diff нет изменений поведения и посторонних правок.

## DEV-002 — Разобраться с локальными CI-воркерами

**Статус:** Запланировано. **Дата:** 2026-11-12.

**Зачем:** оценить запуск GitHub Actions на своей машине и выбрать рабочую схему CI
для StickerSnap. Текущий Pipeline останавливается до первого шага из-за блокировки
GitHub-аккаунта по биллингу; self-hosted runner пока не проверен как способ запуска
при этой блокировке.

**Область:** `.github/workflows/pipeline.yml`, `.github/actions`, окружение runner,
изоляция E2E и инструкция в `docs/DEVELOPMENT.md`.

**Критерии:**

- [ ] Проверить, выдаёт ли GitHub задания self-hosted runner при текущей блокировке;
  зафиксировать результат и отдельно необходимые действия по биллингу.
- [ ] Выбрать с пользователем машину и окружение. Исходный вариант для оценки —
  отдельная Ubuntu x64 VM с Docker и одним runner.
- [ ] Определить зависимости, права, регистрацию, labels и изменения `runs-on`,
  порядок запуска, обновления и очистки runner.
- [ ] Учесть публичный репозиторий: изолировать runner от личных данных, секретов
  и рабочей копии пользователя; определить, какой код допускается к запуску.
- [ ] Проверить конфликты E2E по порту 5198 и общему временному каталогу;
  определить условия безопасного параллельного запуска нескольких workers.
- [ ] На согласованной машине выполнить пробный запуск и записать результат;
  при внешней блокировке указать точную причину и непроверенные части.
- [ ] Зафиксировать выбранную схему и дальнейшие шаги, сохранив текущие проверки CI.

**Исходные сведения:** предварительный разбор workflow показал зависимости от Linux,
Docker и системных библиотек Chromium. Runner не установлен, workflow не изменён.
**Следующий шаг:** проверить ограничения GitHub и согласовать машину для пробного запуска.
