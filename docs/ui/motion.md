# Движение в интерфейсе

Сейчас почти всё в StickerSnap появляется и исчезает рывком: окно публикации возникает целиком за один кадр, поп-ап выпрыгивает в угол, меню «⋯» вспыхивает у кнопки, плашка «Нет видео» толкает холст вниз без перехода. Анимированы только hover кнопок, свитч, полоса прогресса и спиннер.

Этот документ решает, **что двигается, что нет и как**. Он не меняет макеты артбордов 8 «Оповещения» и 12 «Окна и попапы»: их правила появления и закрытия остаются, здесь к ним добавляется только время и траектория.

Реализация отдельной задачей плана (см. «Порядок внедрения» в конце).

## 1 · Принципы

1. **Движение объясняет, а не украшает.** Анимация нужна, когда без неё непонятно, откуда что взялось и куда делось: окно выросло из центра, поп-ап приехал из угла, отрезок исчез из ряда. Если анимация ничего не объясняет, её нет.
2. **Быстро.** Это рабочий инструмент: человек делает одно и то же десятки раз. Всё укладывается в 80–280 мс, большая часть в 120–200 мс. Ничего не заставляет ждать.
3. **Выход короче входа.** Появление тянется на шаг дольше и садится мягко (`ease-soft`), исчезновение на шаг короче и ускоряется (`ease-exit`). Ушедшее не должно висеть перед глазами.
4. **Под рукой ничего не плывёт.** Всё, что тянут мышью (рамка кадра, ручки отрезка, плейхед, ползунки), следует за курсором 1:1, без сглаживания. Повторяемые клавиши (← →, I, O, Ctrl+Z) срабатывают мгновенно. Плавно идут только *скачки*, вызванные кликом по другому элементу: выбрали другой отрезок во вкладках, нажали «Вписать целиком», сменили пресет кадра.
5. **То, что было на экране при открытии, не анимируется.** Анимируется только изменение состояния. Открыли проект с пропавшим исходником: плашка уже стоит, без въезда. Исходник пропал во время работы: плашка въезжает.
6. **Анимация никогда не блокирует.** Элемент принимает клики и фокус с первого кадра появления. Исчезающий элемент сразу перестаёт ловить клики (`pointer-events: none`, `inert`), фокус уходит сразу, а не после анимации. Esc во время появления закрывает окно, анимация разворачивается с текущего места.
7. **Без бесконечных петель**, кроме тех, что значат «идёт работа»: спиннер, радужная полоса отправки, неопределённый прогресс. Ничего не пульсирует, чтобы привлечь внимание: синяя точка на «Моих паках» и метка «Не сохранено» стоят спокойно.
8. **Только `opacity` и `transform`.** Плюс цвета и тени на hover, плюс один приём для схлопывания высоты (`grid-template-rows`, см. раздел 4). Никаких анимаций `width`, `height`, `top`, `left` у крупных блоков и никаких анимаций `backdrop-filter` (стекло над видео и так дорогое).
9. **Уважаем «меньше движения».** При `prefers-reduced-motion: reduce` сдвиги и масштаб исчезают, остаются короткие затухания (раздел 3).

## 2 · Токены движения

Три токена уже есть в `src/web/src/ds/tokens.json` (группа `timing`): `duration-fast`, `duration-base`, `ease-soft`. Их значения не меняются. Добавляются шесть.

| Токен | Значение | Новый | Для чего |
|---|---|---|---|
| `duration-instant` | `80ms` | да | Выход поповера и меню, смена текста в метке и чипе. |
| `duration-fast` | `120ms` | | Hover, нажатие, чекбокс; вход поповера и меню; выход окна и поп-апа. |
| `duration-base` | `200ms` | | Свитч, вкладки, сегменты; вход окна; вход поп-апа; плашка; скачки рамки и отрезка. |
| `duration-slow` | `280ms` | да | Только крупное: переход холста в «Рамку» и обратно, сворачивание окна отправки в поп-ап. |
| `ease-soft` | `cubic-bezier(0.2, 0.8, 0.2, 1)` | | Вход и любое перемещение: быстро стартует, мягко садится. |
| `ease-exit` | `cubic-bezier(0.4, 0, 1, 1)` | да | Выход: медленно трогается, быстро уходит. |
| `ease-linear` | `linear` | да | Прогресс, спиннер, радуга: равномерное «идёт работа». |
| `motion-shift` | `8px` | да | На сколько сдвигается появляющийся элемент (поп-ап снизу, окно сверху). |
| `motion-scale` | `0.96` | да | С какого масштаба вырастает окно и поповер. |

В `tokens.css` это даст:

```css
:root {
  --duration-instant: 80ms;
  --duration-fast: 120ms;
  --duration-base: 200ms;
  --duration-slow: 280ms;
  --ease-soft: cubic-bezier(0.2, 0.8, 0.2, 1);
  --ease-exit: cubic-bezier(0.4, 0, 1, 1);
  --ease-linear: linear;
  --motion-shift: 8px;
  --motion-scale: 0.96;
}

@media (prefers-reduced-motion: reduce) {
  :root {
    --duration-slow: var(--duration-base);
    --motion-shift: 0px;
    --motion-scale: 1;
  }
}
```

Блок `@media` генерирует `tools/build-tokens.mjs`: у токена в `tokens.json` появляется поле `reduced` с его значением при «меньше движения». Так каждый компонент, собранный на токенах, сам становится спокойным, и никто не пишет `@media (prefers-reduced-motion)` руками в каждом CSS-модуле.

Правило для компонентов: **длительности и кривые только из токенов**, никаких `150ms` и `ease-in-out` в CSS-модулях. Те же токены уходят в артефакт дизайн-системы (раздел `timing`), чтобы канвас и код не разошлись.

## 3 · «Меньше движения»

Системная настройка («Эффекты анимации» в Windows, «Reduce animation» в GNOME) приходит в Electron как `prefers-reduced-motion: reduce`. Отдельного переключателя в «Настройках» в MVP нет; если попросят, он ляжет в «Оформление» и будет ставить на корень тот же набор переменных.

При `reduce`:

- Сдвиги и масштаб пропадают (токены `motion-shift: 0`, `motion-scale: 1`), окно и поп-ап просто проявляются. Затухание остаётся: без него появление снова становится рывком, а вестибулярно оно безопасно.
- Скачки рамки и отрезка (принцип 4) и переход холста в «Рамку» происходят мгновенно.
- Спиннер вращается медленнее (уже так: 2,4 с), радужная полоса и неопределённый прогресс стоят статичным градиентом.
- Плавная прокрутка оглавления «Настроек» становится мгновенной. CSS тут не помогает: `SectionNav` вызывает `scrollIntoView({ behavior: "smooth" })` из JS, поэтому поведение надо выбирать по `matchMedia("(prefers-reduced-motion: reduce)")`.
- Hover, нажатие, свитч и вкладки остаются как есть: это короткие изменения на месте.
